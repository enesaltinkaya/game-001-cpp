# Plan

Frame times in `engineStart()` (c-engine/Engine.cpp) are already measured per frame in `utils::timer.elapsed` (ns); the main loop is a plain do-while, so adding an opt-in recorder cannot disturb timing if it is a single vector push per frame. Strategy: add an env-gated frame-time logger that appends each frame's elapsed time to an in-memory `std::vector` and performs exactly one blocking file write after the loop exits (plus a one-line summary: count, mean, stdev, p95, max). Run the game headlessly via `./scripts/run.sh play log 25000` with `ENGINE_FRAME_TIMES_LOG` set so gameplay runs ~25 s and exits cleanly, then analyze the dumped file (histogram, percentiles, spike detection, periodicity) to characterize the instability MangoHud shows. Approach: (1) implement the recorder in Engine.cpp behind `ENGINE_FRAME_TIMES_LOG`; (2) do the single write at the end of `engineStart` before/after teardown as appropriate, logging the output path; (3) capture a 25 s run to /tmp; (4) analyze with a small Python one-off (stdev, p50/p95/p99/max, spike list with timestamps, and whether spikes cluster in time or are periodic); (5) record findings in notes.md so we can link spikes to subsystems (terrain streaming, futureTask, etc.) in a follow-up.

Verification: ENGINE_FRAME_TIMES_LOG=/tmp/frame_times.txt ./scripts/run.sh play log 25000 && wc -l /tmp/frame_times.txt
